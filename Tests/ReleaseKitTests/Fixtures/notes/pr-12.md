# Release notes

- The Dock icon no longer picks up a hand-drawn rim, sheen, and different corners when Sconeos opens. In dark mode it shows the dark icon exactly as macOS draws it.

# What changed?

- The old override (from #10) set `NSApp.applicationIconImage` to `AppIcon-Light.icns` / `AppIcon-Dark.icns`. `generate-icon.swift` draws those by hand with its own superellipse corners, rim gradient, top sheen, and drop shadow. The closed icon is the Icon Composer `AppIcon.icon` compiled into `Assets.car`, which macOS 26 draws with the system mask and Liquid Glass highlights, so the running tile never matched.
- `build-macos.sh` stops bundling the hand-drawn `.icns` pair, and `generate-icon.swift` stops generating them.
- `SconeAppDelegate` now observes `NSApp.effectiveAppearance`. When the app is dark and the system icon style is Default, it sets the Dock image to the dark rendition of the app's own `Assets.car` icon. It renders that through IconServices' `ISAssetCatalogResource`, the same pipeline that draws the closed tile, so mask, corners, glass, padding, and shadow are identical. In light mode, or under any other icon style, it sets `nil`, which restores the bundle icon so the system draws it.
- No public AppKit API selects the dark rendition while icon style is Default. `NSImage(named: NSImage.applicationIconName)`, `Bundle.image(forResource:)`, and `NSWorkspace.icon(forFile:)` all return light under a dark drawing appearance. So the renderer uses a private class. It is guarded by `#available(macOS 26, *)`, `NSClassFromString`, and `responds(to:)`. Any failure falls back to the light bundle icon rather than crashing.

## Closed tile in dark mode

macOS 26 draws closed Dock tiles from the system icon style (System Settings > Appearance > Icon & widget style), not from Dark mode. Under Default, closed tiles stay light even in Dark mode. That is why the running tile can differ from the closed one in dark mode, while matching it in every other respect. To get a dark closed tile too, pick the Dark (or automatic) icon style. The app then leaves the Dock image alone and both tiles come from the system.

# Verification

Test copies were built in the repo's `build/` worktrees on macOS 26.7.1 (UI Dark, icon style Default). Each was launched with `--appearance=light` and with `--appearance=dark`, and compared with the pinned closed tile in the same Dock screenshot. Mean absolute difference is on a 0 to 255 scale over icon-body pixels.

| Comparison | Mean | % px > 8/255 |
|---|---|---|
| Before: running light vs closed | 7.94 | 39.5% |
| Before: running dark (hand-drawn) vs closed | 160.17 | 96.2% |
| Now: running light vs closed | 1.82 | 13.0% |
| Now: running dark vs offline system dark rendition | 1.51 | 5.8% |
| Calibration: closed tile vs offline system light rendition | 2.52 | 12.8% |
| Now: running dark vs old hand-drawn dark | 6.77 | 31.0% |

The system dark rendition and the closed light icon have identical silhouettes: alpha mask IoU 1.0000, and a 0 px corner profile difference. The old hand-drawn dark icon had IoU 0.9712 and corners off by 36.5 px on average.

Live switching of system appearance while the app runs was not exercised, because that would change Dylan's settings. Only the launch flag was used.
