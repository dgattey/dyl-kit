# Release notes

- Sconeos no longer stalls the window at launch while it restores the Spotify session and reads saved room positions.
- Moving or resetting a room pin no longer blocks the map while the change is written to disk.

# What changed?

- `SonosHousehold.waitForTopology` no longer spins once its task is cancelled. `try? Task.sleep` returned at once on cancellation, so the loop polled flat out until the timeout. It now throws `notConverged` when the sleep throws.
- `SpotifyBridge.restore(redirectURI:service:)` derives the vault key and decrypts the token snapshot on a detached task. `SconeStore.live(spotify:)` is async and reads the store files off the main actor. A new `LiveSession` loads both once, and `SconeosMain` shows its content after the session resolves. `SconeAppDelegate` is untouched.
- `moveRoom` and `resetRoom` write through the same serialized async persist path as other edits. The synchronous `save()` is gone. The domain test now waits for the positions file to appear.
- `NetworkDebugLog` sends lines to one `AsyncStream` consumer in order. It used to start a detached task per line, which could reorder lines and pile up tasks under heavy SOAP traffic.
- Releases are signed ad-hoc, so the release workflow never used the `SCONEOS_CODESIGN_P12_*` and `GATTEY_CODESIGN_P12_*` secrets it passed in. They are removed from the workflow and `export-ci-secrets.sh`, and `setup-self-signed-cert.sh` is deleted. The README and script comments now describe ad-hoc signing only.
