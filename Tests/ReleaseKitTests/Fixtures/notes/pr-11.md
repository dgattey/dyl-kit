# Release notes

- **Catch up on skipped updates:** If you skipped versions, the update dialog now lists what changed in each one since, newest first (up to the last 10 versions).
- **Full version history link:** The update dialog links to the complete release history on GitHub.

# What changed?

- Added `scripts/cumulative-release-notes.sh`. Sparkle 2 only renders the `<description>` of the single winning appcast `<item>`, so each new item now gets cumulative notes baked into its description:
  - The new version goes on top as `<h3 style="margin: 0 0 6px 0; font-size: 13px;">X.Y.Z</h3>` followed by its `<ul>`/`<li style="margin-bottom: 6px; line-height: 1.45;">` notes.
  - Earlier versions follow, each under `<h3 style="margin: 14px 0 6px 0; font-size: 13px; opacity: 0.75;">X.Y.Z</h3>`. Bare `<li>` tags get the same style.
  - Previous appcast descriptions are split on their `<h3>` headings. A headerless `<ul>` description (everything before this change) is wrapped with a heading taken from its `sparkle:shortVersionString`.
  - User-facing appcast descriptions always win. GitHub Release bodies are used only for versions no appcast describes. Those bodies are formatted with `format-release-notes.sh` and keep only top-level bullets, because they're developer-facing. Placeholder bodies like `Release v1.0.3` are skipped.
  - Notes are deduplicated by version, sorted newest first, and capped at 10 versions total (`SCONEOS_RELEASE_NOTES_MAX_VERSIONS`).
- Added `scripts/fetch-release-notes-history.sh`, which downloads recent GitHub Releases plus their attached `appcast.xml` assets with `gh`. It's best-effort: if `gh`, auth, or the network isn't available, it warns and falls back to the previous appcast only.
- `scripts/package-release.sh` now builds `Sconeos-X.Y.Z.html` from the cumulative builder, reading the previous `server/public/appcast.xml` before overwriting it. It also passes `--full-release-notes-url "https://github.com/dgattey/scone-os/releases"` to `generate_appcast`, which emits `<sparkle:fullReleaseNotesLink>`.
- Registered the new scripts as release inputs in `.github/workflows/release-macos.yml` and `scripts/macos-release-inputs-changed.sh`, and documented the behavior in `DEPLOY.md`.
- Added `scripts/test-cumulative-release-notes.sh`. It's a no-network dry run over 12 existing versions (1.0.1–1.0.12) releasing 1.0.13, and it asserts:
  - exactly 10 versions are shown, newest first, with the correct heading styles
  - versions are deduplicated, and appcast notes win over release bodies
  - headerless descriptions are wrapped with a version heading
  - placeholder releases are skipped and nested bullets are dropped
  - every `<li>` is styled

## Verification

- `./scripts/test-cumulative-release-notes.sh` passes. Its output is below.
- I also ran a dry run against live GitHub Releases for the next release, 1.0.8. It shows 1.0.8, 1.0.7, and 1.0.6 (user-facing appcast notes), then 1.0.5, 1.0.4, and 1.0.2 (top-level bullets from release bodies). 1.0.1 and 1.0.3 are skipped because their bodies are placeholders.
- I tested the `package-release.sh` notes block in isolation on Linux, both with history and with no `gh` and no previous appcast; the second case outputs just the new version. I couldn't run `generate_appcast` itself here because it's a macOS binary. `--full-release-notes-url` is a documented option in the pinned Sparkle 2.10.0.
